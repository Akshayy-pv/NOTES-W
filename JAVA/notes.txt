? what are JVM, JRE, JDK?


=> "JVM runs the bytecode, JRE provides the environment to run Java applications (JVM + libraries), and JDK is the full development kit (JRE + compiler and other tools) used to write and build Java programs."



JVM (Java Virtual Machine)
    What it is: An abstract machine / runtime engine that actually executes Java bytecode (.class files).
    Role: It's what makes Java "platform independent" — bytecode runs on any device that has a JVM implementation, regardless of the underlying OS/hardware.
    Key job: Loads code, verifies it, executes it, and manages memory (via the garbage collector).
    Note: JVM is platform-dependent in implementation (different JVMs for Windows/Linux/Mac), but the bytecode it runs is platform-independent. It doesn't come alone — it's part of JRE.

JRE (Java Runtime Environment)
    What it is: JVM + a set of libraries/class files (like java.lang, java.util, etc.) + supporting files needed to run Java applications.
    Role: If you just want to run a Java program (not develop one), JRE is enough.
    Formula: JRE = JVM + Libraries

JDK (Java Development Kit)
    What it is: A full software development kit for Java — includes JRE plus development tools like the compiler (javac), debugger, javadoc, jar tool, etc.
    Role: Needed if you want to write and compile Java code, not just run it.
    Formula: JDK = JRE + Development Tools (compiler, debugger, etc.) = JVM + Libraries + Dev Tools

? stack and heap memory in java and how it works ?

=> "Stack memory stores method calls, local variables, and object references in LIFO order — it's fast, thread-specific, and automatically cleaned up when a method returns. Heap memory stores actual objects and is shared across the application, managed by the Garbage Collector. Stack overflow happens with too much recursion; heap overflow happens when too many objects are created without being garbage collected."


Stack and Heap Memory in Java
    Java divides runtime memory into several parts, but the two most important (and most asked in interviews) are Stack and Heap.

Stack Memory
    -Stores method call frames: local variables, method parameters, and partial results.
    -Follows LIFO (Last In First Out) order — each thread gets its own stack.
    -Each method call creates a new stack frame; when the method finishes, its frame is popped off (removed).
    -Stores primitive local variables (int, char, boolean, etc.) directly, and references (pointers) to objects — not the objects themselves.
    -Fast access, memory is automatically allocated and deallocated as methods are called/return.
    -Size is fixed and relatively small; if too many nested/recursive calls happen → StackOverflowError.

Heap Memory
    -Stores all objects and their instance variables (created using new), plus arrays.
    -Shared across the entire application (all threads access the same heap).
    -Managed by the Garbage Collector — objects with no references are eventually removed automatically.
    -Slower access than stack (more overhead), but flexible in size.
    Larger, dynamically sized; if it runs out of space for new objects → OutOfMemoryError: Java heap space.
    -Heap is further divided into Young Generation (Eden + Survivor spaces), Old/Tenured Generation — relevant to GC algorithms.

static Keyword in Java

    The static keyword means a member (variable, method, block, or nested class) belongs to the class itself, not to any specific object. It's shared across all instances of that class instead of each object having its own copy.


1. Static Variables (Class Variables)

    Shared by all objects of the class — only one copy exists in memory (stored in the Method Area / Metaspace, not in each object).
    Useful for values common to all instances (e.g., counters, constants).
    java

    class Student {
        String name;
        static String college = "ABC College";  // shared by all students

        Student(String name) {
            this.name = name;
        }
    }

    public class Main {
        public static void main(String[] args) {
            Student s1 = new Student("Akshay");
            Student s2 = new Student("Priya");

            System.out.println(s1.college); // ABC College
            System.out.println(s2.college); // ABC College

            Student.college = "XYZ College";  // change once, affects all
            System.out.println(s1.college);   // XYZ College
            System.out.println(s2.college);   // XYZ College
        }
    }  


2. Static Methods
    Belong to the class, not an object → called using ClassName.methodName() (no need to create an object).
    Can only directly access other static members (variables/methods) — cannot access instance (non-static) members directly, because there's no object context (this).


    class MathUtil {
        static int square(int n) {
            return n * n;
        }
    }

    public class Main {
        public static void main(String[] args) {
            int result = MathUtil.square(5);  // no object created
            System.out.println(result);        // 25
        }
    }

📌 This is why main() itself is static — JVM calls it without creating an object of the class first:

    public static void main(String[] args) { ... }

Inheritance in Java

    Inheritance lets a class (subclass/child) acquire fields and methods from another class (superclass/parent), enabling code reuse and establishing an "is-a" relationship.

Basic Syntax
java
    class Animal {
        String name;

        Animal(String name) {
            this.name = name;
        }

        void eat() {
            System.out.println(name + " is eating.");
        }
    }

    class Dog extends Animal {
        Dog(String name) {
            super(name); // calls Animal's constructor
        }

        void bark() {
            System.out.println(name + " is barking.");
        }
    }

    public class Main {
        public static void main(String[] args) {
            Dog d = new Dog("Rex");
            d.eat();   // inherited from Animal
            d.bark();  // defined in Dog
        }
    }


Dog inherits name and eat() from Animal, and adds its own bark().

    Types of Inheritance in Java
    Type	Supported?
    Single (A → B)	Yes
    Multilevel (A → B → C)	Yes
    Hierarchical (A → B, A → C)	Yes
    Multiple (class extends 2 classes)	No — use interfaces instead



Ambiguity in Java

    "Ambiguity" errors happen when the compiler can't decide which method/constructor to call because multiple candidates match equally well. Here are the main scenarios

    Conceptual Questions

    1. What is the diamond problem? Does Java have it?

        Java avoids the diamond problem for classes by disallowing multiple class inheritance (extends only one class). But it can still occur with interfaces that have default methods, when a class implements two interfaces with the same default method signature.

    2. Why doesn't Java allow multiple inheritance of classes?

        To avoid ambiguity when two parent classes have methods/fields with the same signature




=>> this and super in Java

    Both are reference keywords used inside instance context (constructors/methods) — this refers to the current object, super refers to the immediate parent class.

this Keyword
1. Resolve variable shadowing (parameter vs field)

    class Student {
        String name;

        Student(String name) {
            this.name = name;  // this.name = field, name = parameter
        }
    }
    
2. Call another constructor in the same class (constructor chaining)

    class Box {
        int length, width;

        Box() {
            this(10, 20);  // calls Box(int, int)
            System.out.println("Default constructor");
        }

        Box(int length, int width) {
            this.length = length;
            this.width = width;
        }
    }

Rule: this(...) must be the first statement in the constructor.

3. Pass current object as an argument

    class Engine {
        void start(Car c) { }
    }

    class Car {
        Engine engine = new Engine();
        void drive() {
            engine.start(this);  // passing current Car object
        }
    }

4. Return current object (method chaining / builder pattern)

    class Builder {
        Builder setName(String name) {
            // ...
            return this;
        }
        Builder setAge(int age) {
            // ...
            return this;
        }
    }

new Builder().setName("Akshay").setAge(23);

super Keyword
1. Call parent class constructor

    class Animal {
        Animal(String name) {
            System.out.println("Animal: " + name);
        }
    }

    class Dog extends Animal {
        Dog(String name) {
            super(name);  // must be first statement
            System.out.println("Dog created");
        }
    }

Rule: super(...) must be the first statement in the subclass constructor. If you don't write it explicitly, Java inserts super() (no-arg) automatically — which fails to compile if the parent has no no-arg constructor.

2. Call parent class's overridden method

    class Animal {
        void makeSound() {
            System.out.println("Some sound");
        }
    }

    class Cat extends Animal {
        @Override
        void makeSound() {
            super.makeSound();  // calls Animal's version first
            System.out.println("Meow");
        }
    }

Output:
    Some sound
    Meow

3. Access parent class's field (when shadowed by subclass field)

    class Animal {
        String type = "Generic Animal";
    }

    class Dog extends Animal {
        String type = "Dog";

        void printTypes() {
            System.out.println(type);       // Dog
            System.out.println(super.type); // Generic Animal
        }
    }


Q: Can you use both this() and super() in the same constructor?

    No. Both must be the first statement, so only one can appear — you can't chain to another constructor in the same class and call the parent constructor from the same place. (Though this(...) will itself eventually reach a constructor that calls super(...), just not in the same constructor body.)


    class Dog extends Animal {
        Dog() {
            this("Rex");  // OK — chains to Dog(String)
        }
        Dog(String name) {
            super(name);  // OK — this constructor calls super
        }
    }

Method Overriding in Java

    Overriding happens when a subclass provides its own implementation of a method that's already defined in its superclass — same method signature, different behavior. It's how Java achieves runtime polymorphism.

Basic Example

    class Animal {
        void makeSound() {
            System.out.println("Some generic sound");
        }
    }

    class Dog extends Animal {
        @Override
        void makeSound() {
            System.out.println("Bark");
        }
    }

    Animal a = new Dog();
    a.makeSound();  // "Bark" — resolved at RUNTIME based on actual object type

This is dynamic method dispatch: even though the reference type is Animal, the JVM calls Dog's version because that's the actual object.

    Rules for Valid Overriding

    Rule	        Detail
    Method          name	Must be exactly the same
    Parameters	    Must be exactly the same (type, order, count)
    Return type	    Same, or a covariant (subtype) return type
    Access modifier	Can't be more restrictive (can widen, can't narrow)

    static methods	Cannot be overridden — only hidden
    final methods	Cannot be overridden at all
    private methods	Not inherited, so can't be overridden (a new method with the same name in subclass is unrelated)

    Exceptions	    Overriding method can throw same, narrower, or no checked exceptions — not broader ones

Polymorphism : means "many forms" — the ability of an object to behave differently depending on the context it's used in. In Java, there are two main types:

1. Compile-time Polymorphism (Method Overloading)

Same method name, different parameters (number, type, or order). Resolved at compile time.

Example

    class Calculator {
        int add(int a, int b) {
            return a + b;
        }

        double add(double a, double b) {
            return a + b;
        }

        int add(int a, int b, int c) {
            return a + b + c;
        }
    }

The compiler decides which add() to call based on the arguments you pass — this is also called static binding.

2. Runtime Polymorphism (Method Overriding)

Same method signature, but a subclass provides its own implementation of a method already defined in its parent class. Resolved at runtime based on the actual object type — this is dynamic binding.

example 

    class Animal {
        void sound() {
            System.out.println("Some generic animal sound");
        }
    }

    class Dog extends Animal {
        @Override
        void sound() {
            System.out.println("Bark");
        }
    }

    class Cat extends Animal {
        @Override
        void sound() {
            System.out.println("Meow");
        }
    }

    public class Main {
        public static void main(String[] args) {
            Animal a1 = new Dog();
            Animal a2 = new Cat();

            a1.sound(); // Bark
            a2.sound(); // Meow
        }
    }

Notice: the reference type is Animal, but the actual method that runs depends on the object type (Dog or Cat) — decided at runtime. This is the classic "upcasting + dynamic method dispatch" pattern.


final 

The final keyword in Java can be applied to variables, methods, and classes — each with a different meaning.

1. final Variable — Value can't be reassigned

Once assigned, it becomes a constant.

    final int MAX_SPEED = 120;
    MAX_SPEED = 150; // ❌ Compile error

For objects, final means the reference can't change — but the object's internal state can still be mutated.


    final StringBuilder sb = new StringBuilder("Hello");
    sb.append(" World"); // ✅ allowed — modifying content
    sb = new StringBuilder("New"); // ❌ not allowed — reassigning reference

Blank final variable: declared without initialization, but must be assigned exactly once (often in the constructor).


    class Car {
        final String engineNumber;

        Car(String engineNumber) {
            this.engineNumber = engineNumber; // must be set here
        }
    }

2. final Method — Can't be overridden

    class Animal {
        final void breathe() {
            System.out.println("Breathing...");
        }
    }

    class Dog extends Animal {
        // void breathe() { } // ❌ Compile error — cannot override final method
    }

Used when you want to lock down behavior that subclasses shouldn't be allowed to change (common in security-sensitive or core logic methods).

3. final Class — Can't be extended/inherited

    final class Utility {
        static void helper() { }
    }

    // class MyUtility extends Utility { } // ❌ Compile error

Famous real-world example: String, Integer, and other wrapper classes in Java are final — this is intentional, partly for security and immutability guarantees.



=> Object class 


    class Car {
        // implicitly: class Car extends Object
    }

This means every object you create automatically inherits a set of methods from Object.

Key methods in Object
1. toString()

Returns a string representation of the object. Default output is ClassName@hashcode (not very useful), so it's almost always overridden.


    class Car {
        String model = "Tesla";

        @Override
        public String toString() {
            return "Car: " + model;
        }
    }

    Car c = new Car();
    System.out.println(c); // Car: Tesla  (without override: Car@1b6d3586)

2. equals(Object obj)

Default implementation checks reference equality (==) — i.e., are they the exact same object in memory. Almost always overridden to compare content.


    class Point {
        int x, y;

        @Override
        public boolean equals(Object obj) {
            if (this == obj) return true;
            if (!(obj instanceof Point)) return false;
            Point p = (Point) obj;
            return x == p.x && y == p.y;
        }
    }
3. hashCode()

Returns an integer hash used by hash-based collections (HashMap, HashSet, HashTable).

Golden rule: if you override equals(), you must override hashCode() too — equal objects must have equal hash codes, or hash-based collections will misbehave.


    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }

4. getClass()

Returns the runtime class of the object — used for reflection, type checks.

    Car c = new Car();
    System.out.println(c.getClass().getName()); // Car

5. clone()

Creates a copy of the object. Requires the class to implement the Cloneable interface, or it throws CloneNotSupportedException. Rarely used directly in modern Java — copy constructors are usually preferred.

6. finalize()

Called by the garbage collector before destroying an object. Deprecated since Java 9 — don't use it; rely on try-with-resources or explicit cleanup instead.

7. Thread-related: wait(), notify(), notifyAll()

Used for thread synchronization (covered when you get to multithreading — not needed right now).



Type Casting 

Type casting in Java means converting one data type into another. It splits into primitive casting and object casting (upcasting/downcasting) — two different concepts that share the word "casting."

1. Primitive Type Casting

=> Widening (Implicit) — automatic, no data loss risk

    Smaller type → larger type. Done automatically by the compiler.

        int num = 100;
        double d = num; // int → double, automatic

    Order: byte → short → int → long → float → double

=> Narrowing (Explicit) — manual, possible data loss

    Larger type → smaller type. You must explicitly cast it.

        double d = 9.78;
        int num = (int) d; // 9 — decimal part truncated, not rounded

        long l = 100000L;
        int i = (int) l; // possible overflow if value exceeds int range

2. Object Casting (Upcasting & Downcasting)

This applies to class hierarchies — converting between a reference of a parent type and a child type.

    => Upcasting — Subclass → Superclass (implicit, safe)

        class Animal {
            void eat() { System.out.println("Eating..."); }
        }

        class Dog extends Animal {
            void bark() { System.out.println("Barking..."); }
        }

        Animal a = new Dog(); // upcasting — happens automatically
        a.eat(); // ✅ works
        // a.bark(); // ❌ compile error — Animal reference doesn't know about bark()
    Always safe, done implicitly.
    You lose access to the subclass-specific methods through that reference (even though the actual object is still a Dog underneath).
    This is the mechanism that makes runtime polymorphism work — the JVM still calls the overridden method based on the actual object type.

    =>  Downcasting — Superclass → Subclass (explicit, risky)

        Animal a = new Dog(); // upcast first
        Dog d = (Dog) a;      // downcast — explicit cast required
        d.bark(); // ✅ now accessible

    Downcasting is only safe when the object actually is an instance of the target type. If not:

        Animal a = new Animal();
        Dog d = (Dog) a; // ❌ compiles, but throws ClassCastException at runtime



ABSTRACT class 
---------------

The abstract keyword lets you declare classes and methods that are incomplete by design


    1. Abstract Class

    A class declared with abstract cannot be instantiated directly. It exists to be extended.

        abstract class Animal {
            String name;

            Animal(String name) {
                this.name = name;
            }

            // Abstract method — no body, just a signature
            abstract void makeSound();

            // Regular (concrete) method — can have a body
            void sleep() {
                System.out.println(name + " is sleeping");
            }
        }

        Animal a = new Animal("Generic"); // ❌ compile error — can't instantiate abstract class
        Subclass must implement all abstract methods

        class Dog extends Animal {
            Dog(String name) {
                super(name);
            }

            @Override
            void makeSound() {
                System.out.println(name + " says Bark");
            }
        }

        Animal a = new Dog("Rex"); // ✅ allowed — upcasting a concrete subclass
        a.makeSound(); // Rex says Bark
        a.sleep();     // Rex is sleeping (inherited concrete method)

    If Dog doesn't implement makeSound(), it must also be declared abstract, or it's a compile error.


    2. Abstract Method

        Declared without a body, ends with ;.
        Can only exist inside an abstract class (or interface).
        Forces every concrete (non-abstract) subclass to provide an implementation.

        abstract void makeSound(); // no {} body, just a signature



INNER CLASS 
------------


An inner class is a class defined inside another class. Java has four types, each with different scope and use cases.

    1. Regular (Non-static) Inner Class

    Tied to an instance of the outer class — it can't exist without one, and it has direct access to the outer class's fields/methods, including private ones.

        class Outer {
            private String name = "Outer Object";

            class Inner {
                void display() {
                    System.out.println("Accessing: " + name); // direct access to outer's private field
                }
            }
        }

        Outer outer = new Outer();
        Outer.Inner inner = outer.new Inner(); // note the syntax — needs an outer instance
        inner.display(); // Accessing: Outer Object

    Cannot have static members (except constants).
    Holds an implicit reference to its enclosing instance.

    2. Static Nested Class

    Declared static — behaves like a top-level class, but namespaced inside the outer class. Does not need an outer instance, and can't access the outer class's instance members directly (only static ones).

        class Outer {
            static int count = 5;

            static class Nested {
                void display() {
                    System.out.println("Count: " + count); // ✅ can access static members
                }
            }
        }

        Outer.Nested nested = new Outer.Nested(); // no outer instance needed
        nested.display(); // Count: 5

    This is the most commonly used inner class type in real code


    4. Anonymous Class

    A class with no name, declared and instantiated in a single expression — typically used to override a method on the fly, often for interfaces or abstract classes.


        interface Greeting {
            void sayHello();
        }

        Greeting g = new Greeting() {
            @Override
            public void sayHello() {

interface
-----------

An interface is a contract — it defines what a class must do, without specifying how. Any class that implements an interface must provide implementations for its methods.

Basic Syntax

    interface Vehicle {
        void start();  // implicitly public and abstract
        void stop();
    }

    class Car implements Vehicle {
        @Override
        public void start() {
            System.out.println("Car starting...");
        }

        @Override
        public void stop() {
            System.out.println("Car stopping...");
        }
    }

    Vehicle v = new Car(); // upcasting to interface type
    v.start(); // Car starting...

INTERFACE — KEY RULES
======================
 
1. Methods
   Implicitly public abstract (unless default/static/private)
 
2. Fields
   Implicitly public static final — must be initialized, can't change
 
3. Instantiation
   Cannot be instantiated directly (new Vehicle() is not allowed)
 
4. Implementing class
   Must implement all abstract methods, or itself be declared abstract
 
5. Multiple implementation
   A class CAN implement multiple interfaces (unlike single class inheritance)
 
6. Extends
   An interface can extend multiple other interfaces
 


Multiple Interface Implementation

    This is the big reason interfaces exist — Java doesn't allow multiple class inheritance, but a class can implement many interfaces:


    interface Flyable {
        void fly();
    }

    interface Swimmable {
        void swim();
    }

    class Duck implements Flyable, Swimmable {
        @Override
        public void fly() { System.out.println("Duck flying"); }

        @Override
        public void swim() { System.out.println("Duck swimming"); }
    }
    Interface fields are constants

    interface Constants {
        int MAX_SPEED = 200; // implicitly public static final
    }

    System.out.println(Constants.MAX_SPEED); // 200
    // Constants.MAX_SPEED = 300; // ❌ compile error — final, can't reassign
    Modern interface features (Java 8+)
    default methods — provide a body, optional to override

    interface Vehicle {
        void start();

        default void honk() {
            System.out.println("Beep beep!");
        }
    }

    class Car implements Vehicle {
        @Override
        public void start() { System.out.println("Car starting..."); }
        // honk() not overridden — uses default implementation
    }

    Vehicle v = new Car();
    v.honk(); // Beep beep!

This let Java add new methods to existing interfaces (like List.forEach()) without breaking every class that already implemented them.



ABSTRACT CLASS vs INTERFACE
============================
 
1. Keyword
   Abstract class : extends
   Interface      : implements
 
2. Inheritance
   Abstract class : Single — one class can extend only one abstract class
   Interface      : Multiple — a class can implement many interfaces
 
3. Fields
   Abstract class : Any type, any modifier (instance state allowed)
   Interface      : public static final only — no instance state
 
4. Constructors
   Abstract class : Yes (called via super())
   Interface      : No
 
5. Methods
   Abstract class : Mix of abstract + concrete freely
   Interface      : Abstract, default, static, private (Java 8+/9+)
 
6. Access modifiers on methods
   Abstract class : Any (public, protected, etc.)
   Interface      : Implicitly public (except private helpers)
 
7. Purpose
   Abstract class : Models "is-a" with shared base state/behavior
   Interface      : Models "can-do" — a pure capability/contract
